As-Is 기획전 구조 이슈

DB 부하 집중 구조

As-Is 현행 구조 요약 : 고객 쿠폰 다운로드 시 회원 DB(구매내역) 실시간 Direct Query 실행 ➔ RDBMS 부하 발생 및 서비스 응답 지연

As-Is 데이터 처리 프로세스 다이어그램 (Client ➔ API ➔ RDBMS)

STEP 1 / CLIENT

고객 기획전 접속

• LFmall 기획전 진입
• 프로모션 메인 페이지 접속
• 브랜드 할인 쿠폰 정보 확인

➔

STEP 2 / ACTION

'쿠폰 다운로드' 클릭

• 다운로드 클릭 요청
• 쿠폰 발급 요청 트래픽 유입
• 이벤트 오픈 시 동시 접속 증가

➔

STEP 3 / SERVER API

회원 DB 실시간 조회

• Direct RDBMS Query
• `MEMBER_MST` & `ORDER_HIST`
실시간 복합 JOIN 쿼리 실행
• 쿠폰 발급 대상 자격 검증

➔

STEP 4 / RDBMS ISSUE

회원 DB 부하 발생

• DB 자원 부하 집중
• 커넥션 풀 자원 부담 증가
• 타 서비스(로그인, 결제 등)
응답 지연 확산 위험

1 1. As-Is 프로세스 주요 문제점

• 실시간 DB JOIN 부하 : 쿠폰 다운로드 시마다 `MEMBER_MST` & `ORDER_HIST` 실시간 복합 쿼리로 DB 응답 지연

• 커넥션 풀 병목 : 기획전 트래픽 집중 시 회원 DB Connection Pool 자원 고갈 및 처리 지연 우려

2 2. 시스템 영향도 및 리스크

• 발급 지연 및 타임아웃 : DB 처리 지연으로 쿠폰 다운로드 요청 타임아웃 발생 위험

• 전사 서비스 영향 확산 : 동일 DB를 공유하는 로그인, 마이페이지, 주문/결제 서비스 응답 지연 전이
