🚨 [STEP 4 / ISSUE] 회원 DB 부하 집중
• 실시간 JOIN 쿼리 부하 : 쿠폰 다운로드 시마다 `ORDER_HIST` 테이블 실시간 집계 쿼리 실행
• DB Connection Pool 병목 : 트래픽 유입 시 회원 DB 커넥션 풀에 부하 집중
• 타 서비스 연쇄 영향 : 회원 DB를 공유하는 로그인, 마이페이지, 주문/결제 서비스 응답 지연 우려
💥 1. As-Is 프로세스 주요 문제점
• 실시간 복합 쿼리 실행 : 고객 쿠폰 다운로드 시마다 `MEMBER_MST`와 `ORDER_HIST` 테이블을 실시간으로 JOIN 및 집계하여 DB 응답 시간이 지연될 수 있습니다.
• DB Connection Pool 부하 집중 : 기획전 오픈 시 순간적으로 많은 동시 요청이 유입되어, 회원 DB 커넥션 풀에 부하가 집중됩니다.
• 데이터 누적에 따른 조회 부하 : 회원 수 및 과거 주문 데이터가 누적됨에 따라 쿼리 조회 범위가 증가하고 DB 자원 소모가 커집니다.
🚨 2. 시스템 영향도 및 리스크
• 쿠폰 발급 지연 및 요청 타임아웃 : DB 응답 지연으로 인해 쿠폰 다운로드 처리가 늦어지거나 요청 타임아웃이 발생할 수 있습니다.
• 회원 DB 공유 서비스 영향 확산 : 동일한 회원 DB를 참조하는 로그인, 마이페이지, 주문/결제 등 다른 서비스까지 응답 지연 영향이 확산될 수 있습니다.
• 서비스 안정성 리스크 : 단일 기획전 이벤트의 DB 부하가 플랫폼 전반의 성능 저하로 이어질 수 있는 구조적 위험이 존재합니다.
