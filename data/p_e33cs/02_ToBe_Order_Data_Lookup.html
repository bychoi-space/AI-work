🚀 1. RDBMS 부하 분산 & 시스템 안정성
• 주문 DB 직접 조회 차단 : 쿠폰 다운로드 자격 검증 시 주문 DB 대신 In-Memory Redis 캐시를 참조하여 RDBMS 부하를 효과적으로 분산시킵니다.
• 타 회원 서비스 영향 최소화 : 이벤트 트래픽 유입 시에도 주문 DB에 직접적인 쿼리가 발생하지 않아 로그인, 마이페이지 등 회원 DB 참조 서비스의 안정성을 확보합니다.
• 유연한 수평 확장성 : 트래픽 증가 시 Redis 캐시 레이어를 수평으로 확장하여 안정적인 처리 용량을 확보할 수 있습니다.
⚡ 2. 빠른 조회 속도 & 이중 배치(Dual Batch) 동기화
• 인메모리 빠른 응답 속도 : RDBMS SQL JOIN 대신 In-Memory 캐시 데이터를 직접 참조하여 쿠폰 발급 자격 조회 속도를 크게 개선합니다.
• 일단위 Bulk + 5분 Incremental 배치 동기화 : 매일 자정 일 단위 전체 벌크 적재로 전체 데이터 정합성을 맞추고, 5분 증분 배치로 최근 주문 내역을 준실시간에 가깝게 반영합니다.
• 서비스 간 장애 격리 : 주문 DB의 일시적인 부하 상황에서도 쿠폰 발급 서비스는 Redis를 참조하므로 안정적인 운영이 가능합니다.
