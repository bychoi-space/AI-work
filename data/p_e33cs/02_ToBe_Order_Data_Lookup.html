To-Be 주문 데이터 조회 개편안

To-Be 주문 데이터 조회 개편 : 회원별 구매 브랜드를 Redis에 1일 벌크 + 5분 증분 동기화 ➔ 쿠폰 다운로드 시 Redis 직결 조회로 DB 부하 0건 달성

데이터 처리 프로세스

STEP 1 / SOURCE RDBMS

주문 RDBMS

• 원천 데이터 저장소

• ORDER_HIST 원본

• 회원별 구매 브랜드 이력

➔

STEP 2 / BATCH ENGINE

배치 동기화 엔진

• 1일 벌크 배치 (자정 적재)

• 5분 증분 배치 (준실시간)

• 회원 구매 브랜드 적재

➔

STEP 3 / REDIS CACHE

Redis 캐시 저장소

• Key: USER_ID / Val: BRANDS

• In-Memory 초고속 참조

• DB Direct Query 차단

➔

STEP 4 / COUPON API

쿠폰 발급 API Engine

• Redis 직결 검증 발급

• DB 직접 조회 0건

• 시스템 부하 위험 해소

1 1. RDBMS 부하 분산 & 시스템 안정성

• 주문 DB 직접 조회 차단 : 쿠폰 발급 검증 시 Redis 캐시 직결 참조로 DB 부하 원천 차단

• 핵심 서비스 안정성 확보

: 기획전 트래픽 집중 시에도 회원 DB direct query가 0건이므로 로그인, 결제 등 핵심 서비스 영향 0%

2 2. 초고속 응답 & 이중 배치(Dual Batch) 정합성

• In-Memory 초고속 응답 : 복잡한 SQL JOIN 연산 없이 Redis Key-Value 직접 조회로 MS 단위 응답

• 이중 배치(Dual Batch) 데이터 동기화

: 자정 1일 전체 벌크 적재 + 5분 증분 동기화 배치 구동으로 최신 주문 이력 준실시간 정합성 보장
