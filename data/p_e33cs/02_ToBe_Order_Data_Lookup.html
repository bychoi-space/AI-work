Redis In-Memory & Dual Batch Sync

To-Be 개편 흐름도 : 주문 DB의 '회원별 구매 브랜드'를 Redis에 1일 벌크 + 5분 증분 동기화 ➔ 쿠폰 다운로드 시 Redis 직결 조회로 DB 부하 분산

To-Be 배치 동기화 & Redis 직결 조회 아키텍처 다이어그램

SOURCE RDBMS

주문 RDBMS

• 원천 데이터 저장소
• `ORDER_HIST` 원본
• 회원별 구매 브랜드 이력

➔

SYNC BATCH ENGINE

배치 동기화 엔진

• 1일 벌크 배치:
자정 전체 구매 브랜드 적재

• 5분 증분 배치:
최신 주문 증분 준실시간 동기화

➔

IN-MEMORY CACHE

Redis 캐시 저장소

• `Key: USER_ID`
• `Value: BRAND_SET`

• In-Memory 초고속 캐시 참조
(주문 DB direct query 차단)

➔

COUPON API ENGINE

쿠폰 발급 API Engine

• 쿠폰 다운로드 요청 시
• RDBMS 직접 조회 미실행!
• Redis 직결 조회 검증으로
주문 DB 부하 0건 달성

1 1. RDBMS 부하 분산 & 시스템 안정성

• 주문 DB 직접 조회 차단 : 쿠폰 발급 검증 시 Redis 캐시를 직결 참조하여 DB 부하 완전 분산

• 핵심 서비스 안정성 : 이벤트 유입 시에도 회원 DB 쿼리가 0건이므로 전사 서비스 정상 작동

2 2. 빠른 응답 & 이중 배치(Dual Batch) 동기화

• In-Memory 초고속 응답 : RDBMS SQL JOIN 대신 In-Memory 캐시 데이터 직접 참조

• 이중 배치 동기화 : 자정 1일 벌크 + 5분 증분 배치로 최신 주문 내역 준실시간 정합성 유지
